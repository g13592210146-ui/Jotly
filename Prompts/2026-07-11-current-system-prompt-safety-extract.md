# 当前系统提示词：日程与风险相关摘录

> 用途：这是本次拟修改范围的原文摘录，不是新的生效提示词。
>
> 当前代码来源：`Jotly/JotlyDeepSeekClient.swift` 的 `systemPrompt`。

## 当前执行规则

```text
- 直接静默执行 (tool_plan)：仅在动作低风险且关键参数完整时使用。
- 确认后执行：对于中高风险动作（如创建生日、缴费等日程/提醒事项），
  必须在卡片选项中挂载 actions，并设置 requires_confirmation = true。
```

## 当前默认规则

```text
- 当处理需要定时提醒或重要重复任务时，若用户表达模糊，
  可通过卡片选项让用户确认，而不要直接静默地替用户做出可能错误的决策。
- 如果所有关键参数齐全，可以直接提供“同意创建”与“仅记录”。
```

## 当前日程工具定义

```text
calendar.create_event
- date / start_date / start_at：格式为 yyyy-MM-dd 或 yyyy-MM-dd HH:mm。
- time：如果用户没明确时间，默认不填（或填 12:30 以示告知）。
```

## 当前历史风险分级中值得保留的规则

来源：`Prompts/2026-06-22-3146b45-3146b45_prompt_backup.md`。

```text
中风险动作：会创建未来提醒、写入 iOS 日历、写入 iOS 提醒事项、发送本地通知。
策略：必须先生成确认卡片，用户确认后才能调用工具。

禁止行为：未经确认写入 iOS 日历、提醒事项或发送本地通知。
```

## 当前问题

1. “中高风险”没有被写成不可例外的硬规则，模型仍可能把日程误判成可直接执行。
2. “关键参数完整”与“所有关键参数齐全”的表述，容易让模型把“明天下午”擅自补成具体时刻。
3. 当前工具说明允许出现 `12:30` 这样的默认值，和“不得替用户预定时间”冲突。
4. 当前提示词保留了食材存放、过期检查等预估型场景，不符合本次收缩范围。
