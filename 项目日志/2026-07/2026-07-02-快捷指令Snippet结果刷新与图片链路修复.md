## 修复问题
- 修复快捷指令系统卡片刷新方式错误导致的重复读图、重复建卡和结果不回显问题。
- 修复 `SnippetIntent.reload()` 触发带图片参数 Intent 反复重载，导致同一张截图被重复读取、重复失败、重复生成卡片的问题。
- 修复截图 Intent 在返回系统卡片前先读取大图，导致首帧空白和明显卡顿的问题。
- 修复快捷指令图片链路和 APP 内图片链路压缩策略不一致，导致图片直传更容易失败或模型返回异常的问题。
- 修复系统卡片显示期间 SwiftUI 轮询反复读取本地大 JSON，造成 APP 和快捷指令卡顿的问题。
- 修复已完成卡片补充修订时，模型已输出新标题和 `reminder.update`，但客户端可能回退成旧卡片和“当前卡片无法识别该指令”的问题。
- 修复加号相册入口只能单选图片的问题。
- 修复多选图片被拆成多张卡片的问题，多图改为同一次模型请求整体解析。
- 调整加号入口为自定义底部相册面板，仅展示相册图片，并支持在选图后按住语音条补充说明。

## 变更点
- 截图/语音主 Intent 只负责创建 operation 与启动后台分析，然后返回 `ShortcutAnalysisStatusIntent(operationId:)`。
- `ShortcutAnalysisStatusIntent` 只读取 operation 状态并渲染纯文字卡片；后续结果更新只 reload 这个状态 Intent，不再 reload 带图片参数的主 Intent。
- 移除系统卡片里的不稳定交互按钮，当前只展示处理中、失败、完成摘要。
- 移除主 Intent 的 `SnippetIntent` conformance 和主 Intent reload，避免系统重新调用带文件参数的 Intent。
- 截图入口改为先创建 operation 并返回状态卡，再在后台异步读取图片。
- 增加 20 秒同类型快捷操作防重入，避免系统重复触发时生成多张卡。
- 移除 snippet 视图内 `.task` 轮询，避免卡片显示时持续读取本地 store。
- 快捷指令 operation 状态最多保留 40 条，避免状态数组无限增长拖慢加载。
- 系统卡片去掉 `ProgressView` 和右侧状态小字，只保留纯文字状态与摘要。
- 系统卡片文案收敛为“正在分析 / 正在分析图片”，完成后显示一句结果简报。
- 图片读取优先使用 `IntentFile.data`，为空时再按可用 content type 与图片常见类型兜底读取。
- 快捷指令图片直传统一使用最大边长 1600、JPEG 0.84 的压缩策略。
- 图片直传 prompt 明确要求模型理解图片后按现有 JSON 结构输出。
- 图片/OCR/模型 JSON 异常失败文案改为更明确的用户可读提示。
- 卡片修订执行链路不再额外嵌套内部 `Task`，按同一条 async 链路顺序写回执行中、完成或失败状态。
- 在 `card_revision` 模式下，工具执行只补充提醒 ID/metadata，卡片标题和正文优先保留模型输出的修订结果。
- 加号入口不再直接使用系统 `PHPickerViewController` 页面，改为 `PHAsset` 自定义底部相册面板。
- 自定义相册面板支持有限高度弹出和上滑全屏，底部放置关闭/发送按钮。
- 自定义相册面板只展示图片网格，不再展示相机、文件、打电话等入口。
- 新增相册权限说明 `NSPhotoLibraryUsageDescription`。
- `JotlyHomeViewModel.insertImages(_:)` 改为一次处理整组图片，OCR 模式合并多张 OCR 文本后提交一次，模型直传模式携带多张图片提交一次。
- `DeepSeekClient` / `JotlyServices` 支持一次请求携带多个 `ImageAttachment`。
- 选中图片后按住语音条，会把最终语音文本和已选图片合并到同一次请求里。
