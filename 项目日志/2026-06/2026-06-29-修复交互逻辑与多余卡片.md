# 2026-06-29 - 修复交互逻辑与多余卡片

## 修改的文件
- `Jotly/JotlyToolDispatcher.swift`
- `Jotly/JotlyHomeViewModel.swift`
- `Jotly/JotlyHomeScreen.swift`
- `Jotly/JotlyHomeScreenSections.swift`

## 修复的问题与变更点

1. **解决语音输入时滑动导致闪退**
   - 之前在长按麦克风识别时，手指轻微滑动会意外触发 `deleteRevealGesture`（左滑删除手势），引发手势状态冲突并导致整个应用直接闪退。
   - 在 `CardListRow` 和 `SquareCardView` 的 `deleteRevealGesture` 的 `onChanged` 和 `onEnded` 阶段加入了 `guard !isVoiceCaptureActive else { return }`，彻底阻断了录音时的左滑冲突。

2. **为正数日/习惯打卡（正方形卡片）增加左滑删除**
   - 之前习惯打卡由于采用了 `SquareCardView` 布局，不支持列表的左滑删除。
   - 在 `SquareCardView` 内部加入了 `deleteRevealGesture` 及红色删除按钮视图，并利用条件 `horizontal > vertical * 2.2` 确保左滑删除不与列表的上下滑动发生打架冲突。
   - 将相关绑定状态（如 `revealedDeleteCardID`、`onDelete` 等）由 `JotlyHomeScreen` 正确下发传递。

3. **修复打卡遗留多余状态卡片问题**
   - 先前用户在连续打卡时，`habit.check_in` 或 `countdown.update` 等工具执行完毕后，系统不仅更新了原有卡片，还留下了无用的 “执行中/已完成” 占位卡片。
   - 现为 `ToolExecutionResult` 增加 `shouldDeleteCallingCard: true` 标记。`JotlyHomeViewModel` 在接收到此标记时，会在底层执行完工具调用后自动删掉占位卡片，保持界面整洁（合并至原卡片）。

4. **优化卡片长按录音回显与状态提示**
   - 按要求更新了 `TaskCardView` 的长按视图（`cardVoiceCaptureOverlay`）。
   - 将“正在录音”状态修正为“正在识别”，并引入 `liveTranscript` 实时回显模型正在转换的文本，并添加了左侧的 `quote.opening` 标识，对齐底部闲置卡片的语音体验。
   - 手指移出卡片区域时，提示文字现在将瞬间变更为“松手取消”或“手指移出卡片区域即可取消”，释放手指则直接取消该次录入。因为本身附加了 `minimumDistance: 0` 的 `DragGesture`，手指长按时自然拦截了 ScrollView 的滑动，满足“按住时手指上下移动不能滑动页面”的需求。
