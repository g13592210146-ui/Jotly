## 修复的问题与变更点
1. **排查并解决“模型返回格式不是有效 JSON”报错隐患**：
   - **真实原因**：用户发出“明天是妈妈生日”的提醒请求，模型在农历生日选项中只传了阳历参数对 `"date": "2026-06-26"`，并未传 `lunar_month` 与 `lunar_day`。
   - **校验阻断 bug**：虽然 `createLunarReminder` 执行器设计了自动将阳历 `date` 转换为阴历的 `else` 兜底逻辑，但在执行前被 `validateBirthdayDatePresence` 拦截，因缺少阴历月/日直接抛出了 `JotlyError.invalidDeepSeekResponse`。
   - **错误码误导 bug**：当执行器抛出 `invalidDeepSeekResponse` 时，在 UI 层的本地化描述为“模型返回格式不是有效 JSON。”，导致误报为 JSON 格式问题。
2. **修复与校验机制调整**：
   - **放行转换**：更新 `validateBirthdayDatePresence` 和 `BirthdayToolExecutor.execute` 中的日期存在性校验。若为农历提醒且缺少显式阴历参数，只要存在可供转换的阳历 `date`，即视为参数完整放行，交由底层的 `else` 分支进行公历转农历计算。
   - **精准报错**：将上述校验阻断时抛出的通用 `invalidDeepSeekResponse` 替换为更有针对性的 `invalidToolParameters("无法识别出农历或可转换的阳历日期信息。")`，保证报错信息与实际错误成因完全吻合，绝不再误报为 JSON 语法问题。
