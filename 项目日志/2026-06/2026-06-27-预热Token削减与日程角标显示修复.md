## 修复的问题与变更点

### 1. 预热模型连接的输入 Token 数量级削减（从 3300+ 削减到约 5 个）
- **成因**：原 `prewarm` 预热方法中直接打包发送了 `Self.systemPrompt` 全局长提示词，导致每次 App 启动时冷唤醒网络连接的开销极高（占用了 3371 个输入 Token）。
- **修复**：修改了 [JotlyDeepSeekClient.swift](file:///Users/gaoxingchen/Documents/Jotly/Jotly/Jotly/JotlyDeepSeekClient.swift) 的 `prewarm(model:)` 逻辑。**在预热阶段不发送全局系统提示词**，仅向模型投递一个微型 User 消息 `[{"role": "user", "content": "ping"}]`。这能够同样触发 SSL 握手与连接预热，但输入 Token 陡降为数个，完全消除了不必要的预热成本。

### 2. 根除设备 12/24 小时格式对日期解析的影响 (POSIX Locale)
- **成因**：iOS 设备的 12/24 小时系统时间设置会直接重写 `DateFormatter` 中指定的 `HH:mm` 模式。如果用户使用 12 小时制，`DateFormatter.date(from:)` 解析标准的 `yyyy-MM-dd HH:mm`（如 `"2026-06-27 14:00"`) 时会直接失败返回 `nil`，导致下次提醒时间失效并 fallback 到显示 `"阳历 提前 0 天"`。
- **修复**：在 [JotlyModels.swift](file:///Users/gaoxingchen/Documents/Jotly/Jotly/Jotly/JotlyModels.swift) 中，将 `dayFormatter` 和 `dateTimeFormatter` 的 `locale` 强制定义为 `en_US_POSIX`。这是 iOS 系统的标准最佳实践，它强制使用 24 小时制模式进行解析，免受用户系统设置的影响，保证下次提醒时间完美解析。

### 3. 去除普通日程中无意义的“阳历 提前0天”角标
- **成因**：普通提醒和日程卡片（`type == "date"`，如羽毛球日程）并非生日，默认显示“阳历 提前 0 天”没有任何语义价值且不美观。
- **修复**：
  - 修改了 [JotlyHomeScreenSections.swift](file:///Users/gaoxingchen/Documents/Jotly/Jotly/Jotly/JotlyHomeScreenSections.swift) 的 `reminderBadgeText` 方法。对于 `lunar` 和 `solar`（生日）之外的类型，如果 `nextTriggerDate` 确实为空，直接返回 `nil`；如果 `nextTriggerDate` 有效，正常回显 `"下次 6月27日 14:00"`。
  - 在卡片头部调用处，仅在返回的 `badgeText` 不为空且非 `nil` 时，才渲染该角标胶囊气泡。普通备忘、记录以及无具体提醒的普通日程卡片现在拥有完全清爽的无角标界面。
