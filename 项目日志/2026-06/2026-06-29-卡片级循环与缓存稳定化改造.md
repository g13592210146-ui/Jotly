# 2026-06-29 卡片级循环与缓存稳定化改造

- `JotlyModels.swift`
- `JotlyDeepSeekClient.swift`
- `JotlyHomeViewModel.swift`
- `JotlyToolDispatcher.swift`
- `项目日志/README.md`

## 修复的问题与变更点
### 1. 建立卡片级循环上下文
- 新增 `AgentRequestContext`，区分 `new_card`、`card_revision`、`option_continue`。
- 普通输入、卡片长按补充、选项继续判断都可以携带统一上下文进入模型请求。

### 2. 收敛长按卡片补充链路
- 长按卡片补充不再单独维护一套模型结果处理逻辑。
- `submitCardSupplementText()` 只负责追加用户输入、保存原始输入、组装卡片上下文，再交给统一处理函数。
- 新增统一的 `handleAgentAnalysis()`，集中处理确认、执行、越界拒绝、卡片更新和对话线程写入。

### 3. 稳定千问缓存前缀
- 固定系统提示词前缀现在包含卡片生命周期规则和生日技能规则。
- 动态信息如当前卡片、历史对话、用户本次补充、执行结果只放在 user prompt 动态区。
- 千问系列仍只对固定前缀加显式缓存声明，避免动态内容污染缓存前缀。

### 4. 补齐已完成卡修改工具基础能力
- 工具层新增 `reminder.update`、`calendar.update`、`calendar.update_event`、`memory.update`。
- 日程/提醒更新 v1 采用“取消当前卡旧产物，再按新参数重建”的方式。
- 工具执行结果会把日历、提醒、通知等产物 ID 写回卡片 metadata，方便后续继续修改。
