## 修复的问题与变更点

### 1. 适配官方最新 DeepSeek V4 Pro 和 V4 Flash 模型的思考模式参数
- **成因**：官方 DeepSeek API 自 2026 年新版起，已废弃原有的专有属性字段并逐步废弃旧模型别名，转为支持以下新的官方参数规范：
  - **启用思考模式**：在 API Body 根级投递结构体 `"thinking": {"type": "enabled"}` 并支持 `"reasoning_effort": "high"`。
  - **禁用思考模式**：在 API Body 根级投递结构体 `"thinking": {"type": "disabled"}`。
  - 原本我们使用 `"enable_thinking": Bool` 发送，虽然兼容百炼平台的 Qwen 系列，但官方 DeepSeek 会直接忽略这个不受支持的 key。由于 V4 模型默认开启思考模式，这就导致 V4 Flash 会一直以思考模式吐出推理流，增加多余的延时和处理开销。
- **修复**：
  - 增设了 `DeepSeekThinkingConfig` 结构体，专门用于编码官方格式的 `thinking` 对象参数。
  - 在 `DeepSeekRequest` 结构中整合并同时定义了 `thinking: DeepSeekThinkingConfig?` 与 `reasoningEffort: String?`。
  - 实现精细控制：**DeepSeek V4 Pro**（推理模型）配置为 `enabled` 并开启 `high` 高推理深度；**DeepSeek V4 Flash**（极速对话模型）配置为 `disabled` 以节省延时与 Token 消耗。
  - 同时保留了 `enableThinking: Bool?` 的兼容支持，以保证阿里云百炼平台（MaaS）上 Qwen 思考模型的控制机制继续生效。
