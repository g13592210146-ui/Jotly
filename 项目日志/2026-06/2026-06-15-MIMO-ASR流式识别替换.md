# Jotly 项目日志 2026-06-15 (日) - MIMO ASR 流式识别替换

## 背景

将 iOS 本地语音识别（`SpeechService`，基于 `SFSpeechRecognizer` / `SpeechAnalyzer`）替换为小米 MIMO ASR 云端模型，实现更高准确率的语音识别。

## 目标

- 替换底层语音识别引擎为小米 MIMO ASR (`mimo-v2.5-asr`)
- 保持实时流式识别体验（说话同时文字逐字出现）
- 避免每次请求重写已有文字

## MIMO ASR API 信息

- **Base URL**: `https://api.xiaomimimo.com/v1/chat/completions`
- **模型**: `mimo-v2.5-asr`
- **认证**: `Authorization: Bearer <MIMO_ASR_API_KEY>`
- **格式**: OpenAI 兼容格式
- **音频格式**: WAV (16-bit PCM) 或 MP3，Base64 编码，上限 10MB
- **语种**: `asr_options.language` 支持 `auto` / `zh` / `en`
- **流式**: 支持 `stream: true`，SSE 格式返回

## 实现方案演进

### 第一版：录音后批量识别（已废弃）

- 录音期间只收集音频，不发送请求
- 松手后将完整音频一次性发送到 MIMO API
- **问题**: 不是实时识别，用户体验差

### 第二版：流式识别但文字重写（已废弃）

- 录音期间每 ~1.5 秒将累积音频发送到 MIMO API (`stream: true`)
- SSE 逐 chunk 返回识别结果
- **问题**: 每次请求发送完整音频（从开头到当前），MIMO 每次都从头识别，导致文字"重写"
  - 例：第1次返回"你好"，第2次返回"你好世界"——UI 看到的是"你好"→"你好世界"（中间过程是重写而非追加）

### 第三版：增量追加策略（当前采用）

- 录音期间每 ~1.5 秒发送累积音频到 MIMO API (`stream: true`)
- **客户端增量处理**: 每次请求拿到完整结果后，只取新增部分追加到已有文字
- 核心状态管理：
  - `confirmedText`: 已确认的文字（不会再变）
  - `streamingText`: 当前请求中正在流式接收到的文字
  - `isRequestInFlight`: 防止并发请求导致文字错乱
- 请求完成后将 `streamingText` 合并到 `confirmedText`
- UI 显示: `confirmedText + streamingText`
- **结果**: 用户看到的文字只会增长，不会重写

## 关键代码文件

- **`MimoASRService.swift`** (新增): 封装 MIMO ASR API 调用
  - `AVAudioEngine` 录音 + 音量回调
  - WAV 格式编码（16-bit PCM）
  - 周期性流式发送（每 1.5s）
  - SSE 解析 + 增量追加策略
- **`JotlyHomeViewModel.swift`** (修改):
  - `SpeechService` → `MimoASRService`
  - 传入 `onTranscript` 回调实时更新 `liveTranscript`
  - `finishVoiceCapture` 使用流式累积的识别结果
  - API 失败时用实时转写兜底

## 遇到的问题与修复

| 问题 | 原因 | 修复 |
|------|------|------|
| 编译错误 | 第72行两语句粘在一起 `JotlyLog.speech.info(...)isRequestInFlight = false` | 拆分语句 |
| "流式发送失败: cancelled" 报错 | 松手时 `stop()` 取消周期性 Task，正在进行的请求被 `Task.isCancelled` 中断 | 检测 `cancel` 关键字，降级为 `info` 级别 |
| `confirmedText` 可能不完整 | `Task.isCancelled` 提前 return 时，`self.streamingText` 可能不完整 | 合并时使用本地变量 `currentStreamingText` |
