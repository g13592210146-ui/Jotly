# Jotly - AI 用户故事

## 项目是什么

一个手机端原生 AI Agent 框架。语音是主入口，卡片是结果呈现，工具调用是执行能力。

用户用一句自然语言表达生活里的需求，AI Agent 在 App 提供的工具框架内理解、执行、记录，并把结果沉淀成卡片。

一句话：随口一说，生活自动成卡片。

不是：记事本、日记 App、倒计时 App、打卡 App、订阅管理 App、个人助理聊天 App。

## 核心产品理念

AI 驱动，不是 AI 点缀。

传统 App 的逻辑：用户选择功能 -> 填写字段 -> 保存 -> 查看模块。

本产品的逻辑：用户说一句话 -> Agent 判断意图 -> 自动调用工具 -> 生成卡片 -> 后续提醒 / 统计 / 回看。

开发时不能先围绕「页面功能」设计，而应该围绕：Agent 能理解什么、能调用什么工具、能生成什么结果。

## 语音是主入口

主交互必须是：长按说话 -> 实时转文字 -> 松手 -> 文字过渡到顶部 -> 形成卡片 -> Agent 处理 -> 卡片回显结果。

用户不能感觉自己是在「填表」或「发聊天消息」，而是感觉：我刚刚说了一句话，App 立刻替我做了事。

## 卡片是结果，不是输入表单

卡片不是让用户填信息的表单，而是 Agent 执行后的结果呈现。

卡片应该告诉用户：
1. 我理解了什么；
2. 我正在做什么；
3. 我还需要你确认什么；
4. 我已经完成了什么。

例如用户说「我朋友小 A 今天生日」，卡片应该展示：已识别为生日 / 重要日期。是否每年提前 3 天提醒你？然后给用户选项。

## Agent 负责动作，App 负责边界

Agent 不应该无边界自由发挥。App 给 Agent 一个明确工具箱，Agent 只能在工具边界内执行。

第一版工具箱包括：创建提醒、创建倒计时、创建周期提醒、增加一次计数、创建订阅记录、创建日记记录、修改卡片、合并卡片、查询已有记忆、生成回看卡片。

## 用户不需要理解模块

用户不应该先选「生日」「倒计时」「打卡」「订阅」「日记」这些模块。

用户只需要说：小 A 今天生日。今天喝了一杯咖啡。Claude 又续费了。今天有点焦虑。明天晚上 8 点打球。

系统在后台自动判断该生成什么卡片。

## 第一版闭环场景：生日提醒

用户长按底部按钮说「我朋友小 A 今天生日」，系统完成：

1. 语音识别成文字；
2. 文字进入首页顶部形成任务卡片；
3. Agent 判断这是生日事件；
4. Agent 判断可以为用户创建每年生日提醒；
5. Agent 判断缺失信息：阳历还是阴历；
6. 卡片变成审批态，弹出选择题式选项；
7. 用户点击或语音补充；
8. Agent 调用提醒执行器；
9. App 创建本地提醒；
10. 卡片更新为已完成状态。

这个场景验证整个产品核心架构：语音输入 -> Agent 理解 -> 卡片审批 -> 工具执行 -> 结果回显 -> 长期记忆。

## 卡片生命周期

processing（AI 正在整理） -> waiting_confirmation（等待用户确认） -> executing（执行中） -> completed（已完成）

或：processing -> waiting_confirmation -> record_only（仅记录）

processing 状态可以展示轻量过程，如「识别日期」「判断提醒」「等待确认」。不要展示技术术语，例如 LLM、Tool Calling、Agent Runtime、正在调用模型。

## 审批选项样式

当 Agent 需要用户确认时，统一弹出选择题式选项，而不是为每个场景单独设计复杂按钮。

生日场景的选项：A 仅记录，不创建提醒 / B 创建阳历生日提醒 / C 创建阴历生日提醒。

用户可以点击，也可以继续语音补充。如果用户继续说「帮我创建日程，是阴历生日」，Agent 要判断这不是一个新任务，而是对上一张等待确认卡片的补充。

## 语音输入交互

参考微信语音输入的核心交互理念，但不照抄视觉。

- 长按底部语音按钮，立即开始录音和实时转写；
- 长按状态下，页面中下部出现半透明语音识别浮层，展示「正在听」+ 实时转写文字 + 语音波纹；
- 松手发送当前识别结果，文本过渡到首页顶部形成任务卡片；
- 短距离滑动：左滑取消 / 右滑编辑文字；
- 单手拇指操作友好，左右区域分明。

## 首页结构（第一版）

非常克制，不放复杂内容：

- 顶部状态栏 / 安全区
- 提示文案：今天想记点什么？说一句话，我帮你整理成卡片
- 顶部任务卡片区域
- 中间大面积留白
- 底部三段式输入栏：左侧相机按钮 / 中间按住说话 + 文字语音切换 / 右侧加号按钮

第一版不展示：今日推荐、本周总结、智能堆叠卡、订阅列表、打卡列表、分类入口、底部 Tab Bar、聊天气泡。

核心只验证：底部语音输入 -> 顶部任务卡片 -> Agent 处理 -> 选择题式审批。

## UI 视觉方向

基于 iOS 26 Liquid Glass 风格构建。

整体要求：原生 iOS 感、轻盈、透明、温暖、克制、高级、真实可开发。不像网页、不像安卓、不像后台系统、不像 ChatGPT 聊天界面。

具体风格：半透明玻璃材质、背景动态模糊、柔和折射、边缘高光、细腻阴影、液态圆角、轻微景深。配色：奶油白 / 浅米色 / 极浅暖灰 / 淡蓝白渐变背景。信息密度低，留白充足。

## Agent 系统架构

六个核心对象：Input、Intent、Tool、Card、Memory、Recall。

流程：用户说一句话 -> RawInput 原始输入 -> Intent Parser 意图识别 -> Card Generator 卡片生成 -> Action Engine 动作执行 -> Memory Store 记忆库 -> Recall Engine 回看引擎 -> Home Feed 首页展示。

## 第一版开发模块

1. 语音输入模块：长按录音、实时语音识别、松手提交、左滑取消、右滑编辑、文本过渡到顶部卡片。
2. Agent 意图识别模块：判断是不是生日、有没有人物、日期是什么、能否创建提醒、是否缺少阳历阴历、是新任务还是补充上一张卡片。
3. 卡片状态模块：管理 processing -> waiting_confirmation -> executing -> completed 生命周期。
4. 选择题审批模块：将 Agent 的确认需求统一渲染为选择题，通用模块，未来订阅、日记、打卡等场景复用。
5. 提醒执行器模块：Agent 只下发指令，提醒执行器负责实际创建通知。第一版优先支持每年生日提醒、提前 3 天提醒、上午 9:00 通知、阳历 / 阴历。
6. 记忆存储模块：保存原始输入、识别文本、卡片、生日事件、提醒规则、用户选择、执行动作日志。

## MVP 边界

做：生日提醒场景、语音输入及实时转文字、松手发送、左滑取消、右滑编辑、文字编辑后发送、顶部任务卡片、选择题式审批选项、执行结果卡片、创建阳历 / 阴历生日提醒、仅记录生日、本地通知提醒。

不做：今日推荐、本周总结、分类模块、复杂多 Agent、多任务并行、订阅管理、打卡统计、日记分析、相册识别、文件识别、健康数据、礼物推荐、生日祝福生成、通讯录匹配、社交发送、复杂动画。
